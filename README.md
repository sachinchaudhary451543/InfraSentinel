# InfraMonitor

InfraMonitor is an infrastructure monitoring and endpoint management platform for tracking device inventory, live CPU/RAM/disk telemetry, alerts, productivity signals, screenshots, remote actions, and administrative configuration from a single web portal.

> Security note: this public README intentionally does not include real credentials, API keys, tenant IDs, client secrets, database files, screenshots, or production configuration values.

## Highlights

- Live infrastructure dashboard with real-time endpoint telemetry.
- Agent-based device monitoring for Windows systems.
- CPU, memory, disk, activity, and process attribution signals.
- Azure/Entra-oriented inventory and identity correlation workflows.
- Remote action queue for diagnostics, repair tasks, and agent operations.
- Employee/device assignment management and productivity reporting.
- License management views and administrative configuration center.
- Docker-oriented deployment files for scalable environments.

## Local development

### 1. Create and activate a virtual environment

Use your preferred Python virtual environment workflow. On Windows PowerShell, activate the project environment before installing dependencies.

### 2. Install dependencies

Install packages from `requirements.txt` inside the activated environment.

### 3. Configure environment values

Create a local `.env` file or set environment variables in your shell. Do not commit `.env` files.

Common values used by deployments include:

- Application client ID
- Tenant ID
- Application client secret
- Production database URL
- Agent enrollment or API key values generated by the portal

Use placeholder values in examples and keep real values in a secure secrets manager.

### 4. Initialize or migrate the database

For local development, SQLite may be used. For production, use a managed PostgreSQL-compatible database and run the migration workflow appropriate for your environment.

### 5. Start the portal

Run the local application entry point from the repository root. The development portal is typically served on port `8765` unless configured otherwise.

### 6. Start the agent

Run the agent only after generating or configuring a valid local agent key. Never hard-code production keys into source files.

## Docker deployment

The repository includes Docker and Compose assets for containerized deployment. Review all environment variables and secret references before starting a public or production environment.

Production deployments should use:

- PostgreSQL or another production-grade relational database.
- Redis or a queue backend for background workloads where applicable.
- HTTPS termination through a trusted reverse proxy or platform load balancer.
- External object storage for screenshots and large artifacts.
- Managed secret storage instead of committed configuration files.

## Security checklist before publishing

- Do not commit `.env`, `config.json`, encrypted secret files, local database files, logs, screenshots, or generated exports.
- Rotate any token or password that was ever pasted into documentation, Git config, terminal output, issue comments, or screenshots.
- Use least-privilege Microsoft Graph permissions and review admin consent regularly.
- Keep agent API keys tenant-scoped and revocable.
- Use HTTPS and secure cookies in production.
- Do not expose the development Flask server directly to the internet.

## Git ignore policy

The repository is configured to ignore common sensitive/runtime artifacts, including:

- Local environment files.
- Runtime configuration backups.
- SQLite databases and sidecar files.
- Logs and generated reports.
- Screenshots and uploaded files.
- Virtual environments and dependency caches.

Review `.gitignore` before adding new runtime directories.
